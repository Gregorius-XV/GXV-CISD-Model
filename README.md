✦ GXV CISD Model-Lite concentrates the complete Change in State of Delivery workflow into one multi-timeframe execution map.

It connects liquidity sweeps, C2 formation, CISD confirmation, displacement, invalidation and projected objectives while displaying up to three higher-timeframe models beside live price.

Instead of reconstructing each component manually, traders can immediately evaluate:

Where liquidity was taken
Whether CISD is confirmed or still developing
Which level invalidates the active model
Where the next measurable expansion objectives are located

CORE CISD ENGINE

The on-chart engine processes the complete model sequence:

Liquidity-sweep detection
C2 identification and locking
CISD level selection
Closed-bar confirmation
Displacement qualification
Post-confirmation invalidation

Active CISD levels are managed throughout their lifecycle. When the underlying structure fails its defined invalidation conditions, the level is removed rather than left behind as obsolete information.

This produces a cleaner chart and a more accurate view of which models remain structurally active.

CONFIRMED AND EARLY CISD

Confirmed CISD displays transitions that have completed the indicator's validation sequence.

Early CISD is an optional live mode that exposes a developing transition before confirmation. It uses separate line styling so provisional information remains visually distinct from a completed CISD.

This allows traders to monitor developing delivery shifts without presenting an intrabar condition as a confirmed event.

THREE HIGHER-TIMEFRAME MODELS

Display up to three HTF models simultaneously, using automatic fractal selection or manually selected timeframes.

Each pane can include:

Live higher-timeframe candles
Higher-timeframe and lower-timeframe liquidity sweeps
Confirmed CISD plotted directly inside the pane
Optional Early HTF CISD
Current-candle countdown
Adjustable candle count, width and spacing
Independent visibility and styling controls

The panes place higher-timeframe structure beside current price, reducing the need to rotate constantly between chart timeframes.

LIQUIDITY-SWEEP VISUALIZATION

Liquidity sweeps can be displayed:

On the main chart
Inside the corresponding HTF pane
In both locations simultaneously

Users can isolate the most recent sweep or retain the latest two, four or all available sweeps for broader structural analysis.

STANDARD-DEVIATION PROJECTIONS

The projection engine maps configurable expansion objectives from one of three sources:

The latest on-chart CISD
A CISD inside an HTF pane
The higher-timeframe C2 candle

Projection ranges can be anchored from open to close or from high to low. Users can define their own positive projection multiples, allowing the model to adapt to different expansion frameworks.

DYNAMIC DEALING RANGES

Build the dealing range from any enabled HTF pane and display it as:

Premium and Discount
Detailed range quadrants

The range can be drawn over its HTF pane, over the main chart or in a dedicated offset area. This keeps price location connected to the same higher-timeframe structure driving the CISD model.

AUTOMATIC HTF KEY LEVELS

The indicator identifies the range high and range low of the highest active timeframe and projects them onto the main chart as labelled key levels.

This keeps the dominant external boundaries visible without additional indicators or repeated manual drawing.

WHY THE MODEL IS DIFFERENT

The central advantage of GXV CISD Model is not any single line or pane. It is the synchronization of the complete analytical sequence:

Liquidity event -> C2 structure -> CISD transition -> displacement -> invalidation -> projected objective

Every component is derived from the same active higher-timeframe framework. Context, confirmation and objectives therefore remain connected instead of being assembled from unrelated tools.

SUGGESTED WORKFLOW

Select automatic fractals or configure up to three manual HTFs.
Identify the active liquidity sweep in the relevant HTF model.
Monitor Early CISD if developing transitions are required.
Use confirmed CISD as the validated change in delivery.
Reference the active invalidation boundary while the model remains valid.
Use SD projections, dealing ranges and key levels to frame potential objectives and opposing liquidity.

SIGNAL BEHAVIOR

Confirmed CISD states use closed-bar validation.

Early CISD is intentionally provisional and can update intrabar until it confirms or is rejected. Live HTF candles also continue to develop until their source timeframe closes.

A confirmed CISD can later be removed when price satisfies its defined post-confirmation invalidation conditions. This is model lifecycle management, not a retroactive change to its original confirmation.
